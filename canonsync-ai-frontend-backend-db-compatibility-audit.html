1. Base URL Mismatch

The single most immediate break — every API call will 404 before touching a controller.

CRITICAL  Frontend targets the wrong API base URL and version prefix
  • Frontend apiClient.js: baseURL = http://localhost:5000/api
  • Backend server.js default port: 3000
  • Backend mounts all routes under /api/v1/
Two problems in one line: wrong port (5000 vs 3000) and missing version segment (/api vs /api/v1). Every frontend request resolves to a dead URL.

3. Payload Mismatches (Detail)

CRITICAL  canonApi.getFacts() — wrong query parameter names
Frontend sends: ?showId=…&search=…&category=…
Backend expects: ?show_id=…&page=…&limit=…
showId is camelCase; the Joi schema validates show_id (snake_case) — the filter is silently ignored and search / category params don't exist at all in the backend schema or repository layer.
CRITICAL  canonApi.addFact() — wrong body key
Frontend sends: { showId, ...fact } (camelCase)
Backend createCanonFactSchema requires: show_id (snake_case), plus required fields category, fact_text.
The showId key will be stripped by Joi's stripUnknown and show_id will be undefined → validation error 400.
CRITICAL  submissionApi.submit() — wrong body keys
Frontend sends: { showId, episodeId, title, content }
Backend createSubmissionSchema expects: { show_id, script, author_name }
  • showId → should be show_id
  • content → should be script
  • episodeId and title have no corresponding backend fields at all
This will always fail Joi validation (missing required show_id, script).
CRITICAL  conflictApi.getBySubmissionId() — wrong URL pattern
Frontend calls: GET /conflicts/:submissionId (path param)
Backend exposes: GET /conflicts?submission_id=… (query param)
The backend router has no /conflicts/:id route for listing; the path param hits the "get by conflict_id" endpoint instead, which will return a single conflict object or 404, not a filtered list.
CRITICAL  conflictApi.resolve() — wrong HTTP method & non-existent path
Frontend calls: POST /conflicts/:id/resolve
Backend exposes: PATCH /conflicts/:id with body { status, reasoning, confidence }
The /resolve sub-resource does not exist. The method is wrong (POST vs PATCH). The body keys { action, reason } don't match backend fields { status, reasoning }.
WARNING  showsApi.create() — extra unrecognised field
Frontend sends: { title, description, seedFacts }
Backend createShowSchema accepts: { title, description }
seedFacts is stripped silently by Joi. No error, but the intent (seeding canon facts on show creation) is never fulfilled — there is no backend logic for this.

4. pgvector & Database Layer

CRITICAL  No database schema / migration exists
The backend/database/ directory does not exist. The git status shows D backend/database/migrations/0001_initial_schema.sql — the migration file was deleted.
There are no CREATE TABLE statements, no pgvector CREATE EXTENSION, and no index definitions anywhere in the project. The tables shows, canon_facts, submissions, conflicts are assumed to exist but nothing creates them.
WARNING  pgvector extension never initialised or verified
The canon_facts table includes an embedding column of type vector, and the model/repository reference it. However:
  • No CREATE EXTENSION IF NOT EXISTS vector; statement exists anywhere
  • No vector index (e.g. CREATE INDEX … USING ivfflat or hnsw) is defined
  • The backend pg driver does not have pgvector registered — the pgvector npm package is absent from backend/package.json
  • No semantic search query exists in canonRepository.js despite the embedding column being stored
The embedding field will be stored as a plain JSON array (or fail entirely), and similarity search is completely unimplemented.
WARNING  No environment file present
No .env or .env.example file exists anywhere in the project. validateEnv() in backend/utils/env.js will throw on startup with "Missing required environment variables" for all five DB vars. The frontend's NEXT_PUBLIC_API_BASE_URL is also undocumented.

5. Other Structural & Integration Gaps

WARNING  Frontend has no pagination support
All backend list endpoints return { data: [...], pagination: { page, limit, total, totalPages } }.
Every frontend API function destructures only data from the response (e.g. return data where data is the full response body). Callers that expect an array will receive an object with a data key and silently lose pagination metadata or break array operations.
WARNING  axios not installed in frontend
apiClient.js imports axios, but frontend/package.json has no axios dependency. The app will crash at runtime with "Cannot find module 'axios'".
WARNING  Deleted auth files leave references unresolved
Git status shows these files were deleted: AuthContext.jsx, AuthProvider.jsx, useAuth.js, AuthApi.js, ProtectedRoute.jsx, login/page.jsx, register/page.jsx.
If any remaining page or component still imports from these paths, it will fail at build time. The backend retains bcrypt and jsonwebtoken dependencies that are now orphaned with no auth routes.
INFO  submissionApi.jsx — wrong file extension
The file is named submissionApi.jsx but contains no JSX. It should be submissionApi.js. Not a runtime error but will confuse tooling and linters.
INFO  No AI/LLM integration layer exists yet
The docs directory describes an AI architecture (fact extraction, contradiction analysis), but there is no corresponding service, queue, or LLM client in the backend. The embedding field in canon_facts implies an embedding pipeline, but no code generates or stores embeddings. The "submit script → detect conflicts" flow exists as a data model only.
